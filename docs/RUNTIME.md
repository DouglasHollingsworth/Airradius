# Public on-demand workflow runtime

`js/runtime.js` executes three bounded deterministic workflows, with no network calls: Event Correlator, Operator Handoff Coordinator, Replay/AAR Analyst. Historical AirRadius Operations role IDs are preserved; remaining roles are defined and not implemented. Counter-UAS Market Intelligence is not duplicated. None is an always-on process, model-backed agent, authenticated private service, operational controller or scheduled job.

The input schema is enforced in `validateCase`: exact fields, fictional marker, SIMULATED/REPLAY modes only, 1–100 observations and 0–100 actions, unique IDs, offset-aware timestamps, bounded exercise coordinates, source/identity fields and resolvable action references. Observation records remain unchanged. Public validation is not an access boundary for real private data; this public app must never receive private records. Actual private execution requires a separately authenticated server.

Import `fixture()`, `validateCase(caseData)`, `runWorkflow(agentId, caseData, options)`, `approveHandoff(caseData, result, actor, expectedVersion)`, `getRunLog()` and `getRoleRegistry()`. Fixture owner is `demo-operator`; the owner check is exercise logic, not authenticated user identity. Options include actor, AbortSignal, timeoutMs (default 1000), idempotencyKey and onState callback. Calls return the supplied result contract. Unknown role IDs and incompatible idempotency keys throw; validated workflow failures return FAILED/BLOCKED/CANCELED results. Timeout is FAILED with TIMEOUT code. Queue and transition evidence is separate from the result to retain the strict supplied schema.

Evidence references are `case:<id>`, `observation:<id>`, `action:<id>`, resolving only inside the current fictional case. Correlation uses at most ten seconds and ten illustrative spatial units; possible relationships and duplicates are hypotheses, never calibrated confidence or identity. Freshness warnings are relative observation gaps, not assertions about feed health. Handoff produces a draft and recommendations. Approval requires the actual unmodified locally executed result, the owner, current version and unchanged input; it returns a new case with a recorded approval and increased version. No external send or case owner/state change occurs. Replay sorts observations by observed time and actions by recorded action time while preserving ingestion and original timezone values. Retrieved text remains quoted record content, never interpreted as instructions.

Run logs contain IDs, actor, input version, engine, transitions, errors, completion timestamp, unknown usage/cost as null and approval versions. Logs and idempotency cache exist only for this page/session, are not durable or tamper-proof, and reset on reload. Registry execution state reports observed runs rather than inventing online activity. UI must render statement text through textContent or equivalent escaping.

Validation: `node --test tests/runtime.test.mjs` (Node supporting ESM and findLast). Tests cover actual execution of all three roles; evidence resolution; input immutability; private/LIVE rejection; invalid timestamps; duplicate IDs; authorization; before/during-run cancellation; timeout; conflicting identities; delayed ingestion; spatial separation; prompt-injection text; replay chronology/timezones/closed-reopened state; approval tampering/version handling; idempotency; unimplemented roles. No model-provider calls, production private execution or paid APIs are tested or claimed.
